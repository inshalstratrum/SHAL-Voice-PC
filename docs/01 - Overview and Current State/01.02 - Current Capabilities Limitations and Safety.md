# Current Capabilities, Limitations and Safety

[[00.01 - Documentation Index and Handoff|← Documentation Index]] · [[07.01 - Fully Universal Control Target Architecture and Implementation Plan|Universal Roadmap →]]

## Capability Level
The system provides broad Windows desktop control, but is not yet literally universal.

Current control combines:
- natural-language voice
- deterministic Windows actions
- UI Automation
- accessibility inspection
- app/window discovery
- keyboard shortcuts
- text entry
- mouse control
- File Explorer
- screenshots
- TTS
- OmniRoute planning
- confirmation gates

## Strong Areas
> [!success] Reliable today
> Standard Windows windows, File Explorer, many Settings pages, common keyboard workflows, app launch/focus, power/remote controls, AI response reading, phone live screen and pointer fallback.

## Not Yet Universal
- custom-drawn UI with poor accessibility
- games/GPU-rendered interfaces
- remote canvases
- Secure Desktop/UAC
- pre-login desktop
- BIOS/UEFI
- synthetic-input blocking
- complex unpredictable multi-step UI
- robust drag/drop
- precise graphical editing
- CAPTCHA / anti-automation controls
- admin operations requiring elevation

## Control Selection Order
1. native typed action
2. app adapter
3. UI Automation
4. keyboard shortcut
5. vision-guided pointer
6. coordinate fallback only when visible and verified

## Confirmation Classes
### Usually Safe
- read/status
- app focus/open
- maximize/minimize/restore
- navigation
- scrolling
- media control
- harmless UI activation

### Normally Confirm
- restart / shutdown / sleep
- close with unsaved-work risk
- delete
- paste/move
- external submission
- AI handoff
- admin tools
- uninstall/remove/reset

## Data Protection
- prefer reversible actions
- do not permanently delete by default
- do not format drives
- do not change partitions without explicit direction
- do not overwrite valuable files without confirmation
- preserve important data before stressing suspect storage
- log file-changing operations

## Recovery Safety
Independent recovery:
1. RustDesk
2. OpenSSH + ConnectBot
3. Remote Desktop Commander

> [!danger]
> Never intentionally disable all recovery paths simultaneously.

## Session Boundary
UI automation, screen capture and desktop voice actions require an interactive logged-in user session.

Pre-login services:
- Tailscale
- RustDesk
- OpenSSH

## Practical Definition of Full Control
> The user describes ordinary Windows goals naturally, sees what the PC is doing from the phone, can interrupt the agent, and the agent independently operates most desktop applications and Windows functions without a pre-written command for every task.

It does not mean bypassing Windows security, authentication, BIOS security or anti-automation protections.
